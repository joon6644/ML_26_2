> 원칙: 시연 스크립트(demo/)는 "결과를 빨리 띄우는 도구"일 뿐이다. 설명은 **실제 프로젝트 파일**(scripts/, eda/, data/reference/)을 열어서 한다.
> 줄 번호는 2026-10-09 기준. VS Code에서 `Ctrl+G` → 줄 번호로 바로 이동.

## 0. 발표 전 준비

- [ ] `python demo/0_train_models.py` 한 번 실행 (약 2분, 이미 해 둠 → `models/`에 세 분야 모델)

- [ ] VS Code 탭을 아래 순서로 미리 열어 두기

## 5. 예상 질문과 답

**데이터**
- *모델에 들어가는 데이터는 어디 있나요?* → 분야별 한 파일 `data/processed/{분야}/model_input.parquet` (농 637만 · 축 90만 · 수 132만 행). 만드는 코드는 `scripts/build_model_input.py`.
- *왜 소매가만 예측하나요?* → 대상이 자취생·1인 가구. 중도매가는 축산에 없고, 소매와 움직임이 달라(월 변화율 순위상관 농 0.63, 수 0.17) 서로 대신할 수 없음.
- *월 통계는 언제부터 쓰나요?* → 실제 공표일(월말 + 20~60일) 이후부터. `build_dataset.py` 89행.
- *EDA는 어디서 했나요?* → `demo/2_eda/` 노트북 5개 (개요·기술통계 / 결측치 / 이상치 / 분포·시계열·계절성 / 변수 관계).
- *그래프가 왜 끊기나요?* → 계절 품목(체리·월동배추), 가락시장 자료는 2018년부터, 축산 2022-02-16 ~ 05-11은 API 원본에 없음.
- *갈치·고등어는 2022년에 끊기고 새 품종이 생긴 것처럼 보이는데?* → KAMIS가 품종 이름을 바꾼 것(예: 갈치 '냉동 중품' → '국산(냉동) 中'). 20건을 `data/reference/variety_rename.csv`에 적고 옛 기록을 새 이름에 이음. 등급 기준이 달라 생긴 가격 차이는 바뀐 직후 6주 / 직전 6주 평균의 비율로 옛 구간을 맞춤 (`scripts/build.py` `link_renamed`). 포도 '수입'처럼 다른 상품이 된 경우와 감귤 '시설'처럼 새로 생긴 상품은 잇지 않음.

**EDA·이상치**
- *이상치를 왜 안 지웠나요?* → 1.5 IQR 밖이 5~19%인데 대부분 실제 시장 변화. 실제로 지워 봤더니 효과 없음(축산은 조사값 14%가 지워짐). 하루짜리 오류만 전날 값으로 바꿈.
- *전날 값 대치는 예측할 때도 하나요?* → 학습 데이터에만. 오늘 튄 값이 하루짜리인지는 다음 날에야 알 수 있어서, 평가·예측은 원래 데이터로 했음.

**모델**
- *결측은 어떻게 처리했나요?* → 채우지 않음. LightGBM은 값이 비어 있는 행을 어느 쪽으로 보낼지 스스로 학습해 '비어 있음' 자체를 신호로 쓴다. 평균으로 채우는 것과 비교했더니 성능이 같거나 약간 나았고 단계가 하나 줄어 이쪽을 택함 (`eda/71_no_impute.py`).
- *예측을 못 하는 경우는?* → 지역 데이터가 부족하면(최근 7일 조사 3일 미만) "최근 조사가 부족해 전국 평균 가격으로 대신 보여드립니다"로 전국 전망을, 전국도 없으면 "최근 조사 없음"과 마지막 조사 가격을 보여줌. 가격 이력 피처 5개 중 4개 이상이 비면(조사 시작 직후 등) "조사 이력이 짧아 정확도가 낮을 수 있습니다"를 붙임 — 이런 행의 방향 정확도는 축 0.67 · 수 0.62 (평소 0.70~0.71). 시연: `배추 서울 2026-07-09`(전국 대체), `가지 대구 2026-09-10`(이력 짧음), `체리 서울 2025-12-15`(조사 없음), `들깨 서울`(소매 미조사).
- *빠진 품목이 있나요?* → 데이터 때문에 지운 품목은 없음. 109개 중 5개(깐마늘(수입)·들깨·메밀·피마늘·북어)는 KAMIS가 소매가를 조사하지 않아(중도매만) 소매 전망이 없음. 14개(가지·부추·키위·꽃게·바지락 등)는 2025년 이후 소매 조사가 시작돼 학습 기간 소매 데이터가 없고, 이력이 짧은 동안 경고 문구가 붙음. 가공식품은 가격이 거의 안 변해 예측 대상에서 제외.
- *1년 중 일부만 조사되는 품종은?* → 조사되는 기간에만 예측. 철 초반엔 4주·13주 변화율이 비어 있지만 작년 같은 시기 값으로 판단. 철 끝 4주 전부터 전망을 숨기는 규칙은 서비스 구현 때 추가 예정.
- *왜 LightGBM 하나인가요?* → XGBoost·CatBoost와 평균하는 앙상블도 했지만 세 모델의 오차 상관이 0.95~0.99로 거의 같아 이득이 작았음(농 R² +0.01~0.02, 축·수는 잡음 수준). 학습 시간 15배·관리할 모델 3배에 비해 얻는 게 적어 하나로. Ridge·RandomForest·MLP 등 다른 계열도 섞어 봤지만 다양하지 않거나(오차 상관 0.84~0.96) 너무 약했음.
- *딥러닝은요?* → MLP를 시험했는데 처음 보는 값에 불안정(농산 R² −1.96), 시스템도 복잡해져 제외.
- *학습 정답 1~99% 자르기가 뭔가요?* → 정답(4주 변화율)의 극단값 상하위 1%를 경계값으로 바꿔 학습. 예: +169% → +14.9%. 데이터·평가는 그대로.
- *확률이 '방향이 맞을 확률'이 아니라 '1% 넘게 움직일 확률'인 이유는?* → 사용자가 "오를 확률 70%"를 읽으면 실제로 오른다고 받아들임. 방향만 맞을 확률로 쓰면 거의 안 움직인 경우를 빼고 세서 숫자가 부풀려짐(예: 같은 예측이 62% vs 40%).
- *예측을 얼마나 믿을 수 있나요?* → 카드에 "4주 뒤 1% 넘게 오를(내릴) 확률 약 x%"를 1% 단위로 표시. 확률 = a + b·ln|예측 크기| 선형회귀 하나(분야별 계수 2개) — 예측이 커질수록 처음엔 가파르게, 점점 완만하게 오르는 로그 곡선 — 예측이 2배 커지면 확률이 약 12~13%p 오름. 그림: `eda/figures/direction_prob_curve.png` (파란 점 = 학습에 안 쓴 예측을 예측 크기 순으로 1,000행씩 묶은 실제 적중률, 전부). 평가는 검증(2023~24)으로만 맞춘 식을 테스트(2025~26)에 대어 봄 → 실제와 대부분 ±5%p 안 (`eda/73_direction_prob.py`). 카드에 쓰는 계수는 학습에 안 쓴 예측 중 정답이 나온 것 전부(2023~2026-09)로 다시 맞춤 — 실제 운영에서 정답을 못 보는 건 마지막 4주뿐이라서. 50% 이하면 "신뢰성이 낮으니 판단에 주의하세요". 상한은 분야별로 예측 크기 상위 1%가 실제로 맞은 비율 — 농 97% · 축 89% · 수 86%. 곡선이 그 높이에 닿으면 그 뒤는 수평(가장 큰 예측들이 실제로 맞은 만큼만 말함). 상한이 없으면 예측 약 40%에서 100%가 되는데, 4주 뒤 가격에 100%는 틀린 숫자라서. 기간에 따른 흔들림(예: 2026 축산은 확률이 실제보다 높음)은 어떤 식으로도 미리 반영할 수 없어 감수 — 불확실성에 대한 추정이라는 점을 그대로 설명. 처음엔 등위 회귀(계단 모양), 그 전엔 세 모델 합의를 썼지만 합의는 결국 '예측이 큰가'와 같은 정보(91~94% 겹침)여서 바꿈.

**평가**
- *R²가 낮지 않나요?* → 지역·시장 잡음 때문에 구조적 상한이 있음(수산 0.27). 사용자 판단에 중요한 건 방향이고, 방향 정확도 0.70~0.73(우연 0.50), 큰 변화(10%+)에선 0.81~0.87.
- *방향 정확도는 어떻게 계산하나요?* → 실제 변화가 ±1%를 넘은 날만, 예측과 실제의 부호(+/−)가 같은 비율. 예측 크기는 보지 않음(+0.2% 예측도 '오른다').
- *베이스라인은 뭔가요?* → 최근 7일 평균이 4주 동안 유지된다고 보는 예측(변화율 항상 0%). 방향을 말하지 않으므로 방향 정확도는 없음(우연 수준 약 0.50).
- *테스트셋은 몇 번 봤나요?* → 피처·모델 선택은 검증셋(2023~24)으로만. 테스트(2025~26)는 최종 평가용. 검증과 테스트 성능이 비슷해 과적합이 없다는 근거.
- *튜닝은 했나요?* → 했지만 여러 시드로 확인하니 개선이 잡음 수준이라 기본값 유지.
- *재학습은 얼마나 자주?* → 연 1회. 해마다 직전 해까지 학습해 다음 해를 예측하는 전진 검증으로 확인(이전 구성 기준).
